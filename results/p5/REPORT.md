# P5：统一评测与结论校准

2026-10-19，Mac M4 Max / MPS，Python 3.12.15。P5 完成统一评测、冻结基准、
配对统计和本地 Judge 校准；没有新增训练或重选 P4 检查点。
**独立新题未证明 GRPO 相对 SFT 有稳定能力收益；小 Qwen Judge 校准失败，已关闭模型排名。**
这是评测体系的验收，不是模型能力提升或一般 Judge 可靠性的验收。

## 协议与证据

正式运行来自干净提交 `9e87760f5b63fdc18c28b16663b3610774ad0a6a`，
执行源与配置 SHA256 为 `b2b0a89cfc47ee355507e7279ec3d76b9e1b8cdefc683f5346ca5ad01896fa6b`。
[manifest](reference/manifest.json) 保存环境、配置与时间；JSON/NPZ 逐文件哈希见
[artifacts](reference/artifacts.json)，产物约 3.2 MB。原始模型依赖仍在 P3/P4 的 reference 中。

- P3：加载三个真实预训练权重，在原四个测试章节重新计算全部 23,061 个 target token 的损失。
- P4：导入原 32 题 × 三种子 × 三种方法的逐题记录，重新评分并复核独立算术 oracle。
  archive adapter 固定原 32-token 协议，不把旧输出冒充新推理。
- 新评测：同一原生 Qwen 基座加九个冻结 adapter，实际生成 1,080 条回答。
  基座仍为 `Qwen/Qwen2.5-0.5B-Instruct` revision
  `7ae557604adf67be50417f59c2c2f167def9a775`，保留原 tokenizer/template、float32、q/v LoRA。
  每次生成前恢复对应 adapter，避免共享模型状态污染身份。

新协议为 greedy、最多 64 个新 token、batch 8、无 repetition penalty 或采样过滤。
[benchmarks](reference/benchmarks.json) 保存完整问题、gold、来源和题集哈希：

| 题集 | 共享题目数 | 构建和解释边界 |
|---|---:|---|
| 新结构模运算 | 64 | 四个 P4 未见 AST 结构；小/大操作数各半；每题族答案 0–7 均衡；AST 与展开式独立验证 |
| GSM8K 固定子集 | 32 | 从固定上游 1,319 道测试题按 RNG 1701 抽取；MIT 许可及原始哈希随仓库保留 |
| 上下文颜色检索 v2 | 12 | 两个房间、一个目标颜色；显式要求只回答颜色词；仅用于窄域格式与参考检索诊断 |

GSM8K 只向模型提供问题，不提供解题过程或 gold。它采用自定义直接回答 XML 提示与固定预算，
**不是完整 GSM8K/标准 CoT 分数，不能与榜单比较；公开题的预训练重合未知。**
新结构仍复用加减乘余数等基础操作，不代表整个数学能力的独立覆盖。

## 新题结果

表中是严格正确率：数值题必须完整输出 `<answer>NUMBER</answer>`，颜色题必须为单一颜色词，
且均须未截断。三种子使用同一批题目；均值不是三倍独立题目数。完整题族/难度分层、
Wilson 区间、内容诊断、格式率、截断和失败类别保存在 [evaluations](reference/evaluations.json)。

| 检查点 | 新结构算术 /64 | GSM8K 子集 /32 | 颜色检索 /12 |
|---|---:|---:|---:|
| 基座 | 0 | 0 | 12 |
| SFT 42 | 9 | 0 | 10 |
| GRPO 42 | 9 | 0 | 10 |
| 筛选监督 42 | 10 | 0 | 9 |
| SFT 7 | 8 | 1 | 10 |
| GRPO 7 | 8 | 1 | 10 |
| 筛选监督 7 | 8 | 1 | 10 |
| SFT 2026 | 11 | 1 | 12 |
| GRPO 2026 | 11 | 2 | 12 |
| 筛选监督 2026 | 11 | 2 | 12 |
| SFT 三种子均值 | 14.583% | 2.083% | 88.889% |
| GRPO 三种子均值 | 14.583% | 3.125% | 88.889% |
| 筛选监督三种子均值 | 15.104% | 3.125% | 86.111% |

算术题的固定常量答案基线为 12.5%。后训练模型算术格式率均为 100%，但答案正确率仍低。
基座算术格式率及本协议内容正确率均为 0；不能仅用格式变化说明训练获得了计算能力。

GSM8K 的三种子内容诊断均值对 SFT/GRPO/筛选监督均为 3.125%；严格分数的小变化没有转化为
更高的可提取数值答案均值。SFT 2026 对 `gsm8k-test-1044` 输出 `<answer>1</answer> inches`，
内容命中但违反完整 XML 约定。各模型也存在错误答案与截断，不能把严格失败全归因于解析。
该内容诊断只覆盖单个 XML、裸数字或最终 `####`，不从自由推理中猜测最终答案。

颜色检索的单一颜色提及诊断对全部模型为 100%；例如 `coral stones` 会因违反显式单词约定
被严格评分拒绝。**这些严格差异是格式遵循现象，不能据此声称事实检索能力退化。**
提及诊断也不是能处理否定、幻觉的一般事实性评分。

## 配对变化与不确定性

每个种子独立计算精确双侧 McNemar；新题面板的 18 个 suite/method/seed 检验一起做 Holm 校正，
校正后的 p 均为 1。原 P4 面板另有六个检验。报告不把依赖的三种子题目合并成一次 McNemar。
跨种子差值按**题目**在题族内重采样 4,000 次，每次保留该题全部固定种子结果。

| 新题集 | GRPO − SFT 均值，百分点 | 条件 percentile 95% 区间 |
|---|---:|---:|
| 新结构算术 | 0.000 | [−2.083, 2.083] |
| GSM8K 子集 | +1.042 | [−2.083, 4.167] |
| 颜色检索 v2 | 0.000 | [0, 0] |

颜色题区间为零只表示这批题上的配对标签没有变化，不证明总体等价。
算术 GRPO 2026 实际有两胜两负，不能把相同总分理解为逐题相同。
这些区间条件于既定种子/题族，不估计新训练种子或未见题族的总体不确定性；少题、低正确率
也限制了统计功效。“没有证明收益”不等于“证明方法无效”。详见 [comparisons](reference/comparisons.json)。

统一重评完整复现 P4 旧标签。旧题上 GRPO − SFT 均值为 +4.167 个百分点，条件区间 [0, 9.375]；
唯一有变化的 GRPO 2026 为五胜一负，原始精确 p=0.21875，六项 Holm 后为 1。
旧题提升与新结构题零均值变化一起表明：当前预算不足以支持稳定迁移收益的结论。
见 [P4 重评与统计](reference/p4_comparisons.json)。

## Judge 校准：格式可解析不等于可靠

使用未更新的同一 Qwen 基座充当本地 Judge。规则生成 16 对校准、16 对独立审计样例，
每对交换 A/B 顺序，共 64 次真实判断；包含直接正误、冗长错误、候选指令干扰、双正确平局。
规则 gold **不是人工偏好标注**。预先固定 agreement≥85%、parse≥95%、顺序一致≥90%，
校准与审计必须全部通过；即使通过，也仅用于参考约束的颜色正确性。

| 集合 | gold 一致率 | 可解析率 | 交换顺序后一致率 |
|---|---:|---:|---:|
| 校准 | 50.0% | 100.0% | 43.75% |
| 独立审计 | 50.0% | 100.0% | 31.25% |

双正确平局类一致率为 0。门槛失败后，[judge_panel](reference/judge_panel.json) 明确记录 disabled，
没有用这些判断产生模型质量排名。完整候选、gold、顺序与生成 token 在
[judge_calibration](reference/judge_calibration.json)；该负结果不能外推到其他大小、模型或提示，
同源 Judge 也不构成独立的能力佐证。开放回答的一般人工偏好评测仍未完成。

## 协议缺陷与修复证据

初次运行 v1 的提示只要求 concise，评分器却只接受更窄的答复模板，误罚了合理短答。
[原始审计](protocol-audit/context-v1.json) 保留当时干净代码版本、全部颜色题与输出；该轮不用于质量排名。
v2 明确要求一个颜色词，并使用匹配的严格解析器，随后重新冻结、运行整个面板。
题目、模型、训练设置未变，数值题和 Judge 提示/预算也未调整。

**修复发生在观察输出之后，v2 是描述性协议验证，不能宣称未经观察的确认性测试。**
两轮真实 MPS 推理中，960 条未改动的数值题记录及 64 次 Judge 记录逐 token 完全一致，
[replay](reference/replay.json) 保存分模型哈希；颜色 v2 因提示变化另行报告，不能当作模型提升。

## 复现与验收

```sh
uv sync --locked --all-extras
uv run --locked --all-extras python -m kaleido.demos.model_evaluation
uv run --locked --all-extras python -m kaleido.demos.model_evaluation --fixture --config configs/p5_smoke.json
uv run --locked --all-extras pytest
uv run --locked --all-extras ruff check .
uv run --locked --all-extras ruff format --check .
uv build
```

正式入口默认 MPS，首次需要固定约 1GB 基座缓存；CPU 可通过配置选择。
它重新加载仓库内 P3/P4 工件，无训练更新；新尝试写入唯一 runs 目录。
fixture 是离线随机 tiny Qwen，仅检验接线，仍真实重评 P3 和 P4 档案，不作为能力证据。
正式评测耗时 51.37 秒；主面板生成 10,680 tokens、输入 78,670 tokens，Judge 另生成 128 tokens。
这些是本次总运行成本，未声称为推理延迟/吞吐基准，也不包括原始 P3/P4 训练成本。
